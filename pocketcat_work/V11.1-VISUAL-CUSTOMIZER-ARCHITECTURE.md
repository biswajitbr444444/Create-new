# V11.1 Visual Customizer Architecture

The Visual Customizer is a control-plane presentation system. It stores versioned visual configuration rather than rewriting PHP source files. The editor is available only to authorized Super Admin sessions and can be opened explicitly with `?visual=1`.

## Data flow
Browser DOM -> local command history -> encrypted/local draft architecture -> review -> `/api/admin/visual-engine/?action=publish` -> validated immutable version -> atomic active-version transition -> client invalidation.

## Security boundary
The visual engine never grants content access to E2EE/BYOS workspaces. Custom JavaScript is policy-gated and disabled by default. DOMPurify should be used for trusted HTML transformation, but arbitrary JavaScript requires a separate sandbox origin and CSP.

## Production deployment
For high availability, run scheduled publishing from a real scheduler/queue, use SSE or WebSockets for cache invalidation, place the application behind a WAF/CDN, and use immutable version pointers for zero-downtime releases.
