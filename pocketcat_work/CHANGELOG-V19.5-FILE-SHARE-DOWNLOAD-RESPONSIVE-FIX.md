# PocketCat V19.5 — File Share Download & Responsive Fixes

## Changelog

- **Public shared-file downloads** → share tokens generated by `file_share_token()` are `fs_` plus 44 hexadecimal characters (47 characters total), but the asset endpoint required 48 characters and rejected every generated token → validate the token format and exact generated length pattern so shared previews/downloads resolve to the real file bytes.
- **Download error handling** → failed asset lookups could be treated by browsers as a file named `asset.html` → return explicit plain-text errors with `nosniff`; keep valid downloads on the binary streaming path with original filename headers.
- **File Storage page header** → on narrower CSS viewports, flex sizing could collapse the heading to one character per line → force the heading/actions into a stacked layout below 1100px and reflow action buttons on phones.
- **Media Library bulk download** → a successful HTTP response containing an HTML/JSON error page could be saved with an archive extension → reject non-file content types, empty responses, and use UTF-8 `filename*` when provided.
- **Cache/versioning** → bump Media Library assets and project `VERSION` to 19.5.

## Verification scope

PHP/JavaScript syntax, archive integrity, token-generation/validation consistency, and static route-flow checks are run against the packaged source. Production authentication, database, cloud-storage and real-device tests require the deployed environment and are not claimed here.
